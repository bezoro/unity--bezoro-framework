# Working on the shared Unity utilities

This repository root is the Unity project. Its current utility source is the embedded `com.bezoro.unity-framework` UPM package at `Packages/com.bezoro.unity-framework`. The root project resolves the pure C# Framework through Package Manager. Chess Crush retains its separate legacy installation at `Assets/_Bezoro/Unity`; the project migration does not modify that game. Source and test trees retain their Unity `.meta` files and assembly names.

Edit the embedded package in this repository directly. Consumers install a published revision using the Git URL subpath `?path=Packages/com.bezoro.unity-framework`, or choose that directory's `package.json` for a disk installation. Independent clones share committed changes through normal Git operations. A consumer's immutable PackageCache is not an editable source checkout.

Commit and publish utility changes here before publishing a consuming project's dependency update. A framework commit or push does not update a consumer automatically. The root Unity project layout replaces the old whole-repository Assets installation; a legacy consumer must remove that installation and migrate to UPM deliberately. Do not install both source copies. Do not update a game's manifest, lock or submodule unless the user requests it.

Check the current branch before editing, preserve dirty work, and avoid forced updates. Legacy submodule tooling is not a migration mechanism for the new package subpath.

Keep Unity and pure C# roles separate. `bezoro/framework` publishes `com.bezoro.framework` on its `upm` branch. The root `Packages/manifest.json` pins an immutable published Git revision and enables this embedded package's tests. Keep the package manager's generated lock after a real resolution; do not copy the package's DLLs into Assets or edit PackageCache. Git dependencies must be declared by the consuming project because UPM does not support Git dependencies between packages. Existing DLL-name references in assembly definitions select the UPM-provided assemblies. Third-party content and editor feedback audio remain outside this repository. The audio normalizer still defaults to the legacy consuming project's `VO` folder; another project should choose its own audio folder in the tool.

Use the root project's exact Editor for local work. The character-controller and commercial drawing integrations have been removed rather than replaced with substitutes. Package tests use their own reflection and must not depend on consuming-game assemblies. Preserve retained `.meta` files, GUIDs, assembly references, and serialized asset references when changing utilities. Root project assets, settings, CI tools and this documentation are outside the distributed package.

The root `.gitattributes` retains the consuming game's existing line-ending and Git LFS policy. Install Git LFS before cloning or publishing assets covered by its filters, and fetch LFS objects when needed. Keep this policy with the framework so its Git blobs use the same normalization as the game source. Before an authorized framework branch push, run `git lfs push origin <framework-branch>` if a Git LFS pre-push hook is unavailable; upload the LFS objects before publishing the game pointer.
